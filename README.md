# FrameRudiments

**Beat-synchronised visualisation, compositing and video rendering — driven by real DanceRudiments motion and source-pinned StemLab timing.**

Experimental 0.4.36: [capture MIDI CC/pitchbend as finite source-clocked takes](docs/midi-controls-m15.md)
and replay through the ordinary compositor, alongside the released [OSC route](docs/osc-controls-m15.md).
Native MIDI capture uses an explicitly selected input on qualified Python 3.11/3.12 hosts;
ordinary rendering, including Python 3.13, opens no MIDI input or network socket.
[Actual 60 fps MIDI demonstration](https://kieransimkin.github.io/FrameRudiments/m15-5-midi/).

Create procedural music visuals, character composites, animated typography, particles, fractals, spatial effects and transitions. Preview the same render pipeline on the [CI-generated demo site](https://kieransimkin.github.io/FrameRudiments/).

## Get started

Requires **Python 3.11+**, [FFmpeg/ffprobe](https://ffmpeg.org/) for encoded output, and a font file you have permission to use. GPU visualisers and shader runtimes are opt-in.

```bash
python -m pip install framerudiments

# Create a reproducible example project (prints the project JSON path):
framerudiments demo ./my-demo --font /path/to/your-font.ttf

# Inspect pinned inputs, render or explore the native clock:
framerudiments plan ./my-demo/project.json --output ./plan.json
framerudiments render ./my-demo/project.json --output ./render-output
```

For local development, clone the repository and `python -m pip install -e '.[dev]'`. Native CI uses [separate setup and qualification budgets](docs/ci-setup-budget.md). See [project format](docs/project-format.md), [compositing and effects](docs/effect-graph-design.md), [M11 video I/O](docs/video-io-m11-4.md) and the [implementation roadmap](docs/unified-effects-transitions-rendering-roadmap.md).

## Rendering architecture

**Pinned media and timing → DanceRudiments source-clocked motion → native FrameRudiments layers and effect graph → temporal effects / feedback → validated FFmpeg output.**

The renderer keeps source time and authored frame identity separate. It supports random-access native rendering, independently hash-checked dependencies, bounded resource use, exact rational video frame timing, and frame receipts. Optional Butterchurn/projectM effects are treated as stateful external runtimes with their own reconstruction constraints.
