# M9.5 — Pinned shader goldens and renderer receipts

**Status:** deterministic host-reference PNGs and mandatory EGL comparison implemented. Exact-head CI and independent physical-AMD/Intel/NVIDIA acceptance must be observed; this document does **not** claim those runs occurred.

The five fixed **64×48 RGBA8** reference images in [`media/gl-goldens`](media/gl-goldens/) exercise the full-file-pinned, explicitly trusted GL Transitions ABI. These PNGs were generated by an **independent integer host model**, not captured from the GPU. Required EGL tests must execute the *actual* GLSL and compare **all pixel bytes exactly** before declaring the goldens accepted. Only genuine device runs produce a GPU qualification receipt.

The test inputs are synthetic, opaque, 16-step ramp patterns specified byte-for-byte in `gl_transition_goldens.synthetic_sources`. No songs, private assets, remote shaders or AI models are used. Input channels are multiples of 16, so quarter/half/three-quarter RGB blending is exactly representable in 8-bit output; this avoids false failures caused by rounding ties in less constrained visual samples. Existing M9.2/M9.3 coverage separately exercises translucent inputs and tolerances. M9.5 does **not** claim visual/perceptual sign-off or broad floating-point shader parity.

## Immutable reference manifest

`media/gl-goldens/manifest.json` (`framerudiments.gl-transition-goldens.v1`) records the deterministic source generator, pixel dimensions, full-file SHA-256 for every pass, output PNG SHA-256, output RGBA pixel SHA-256, explicit progress/time/frame-index values, and restricted-shader policy version. The `reference_kind` deliberately identifies the PNGs as **host references, not real GPU captures**. Every test verifies the manifest and pins *before* a GL context is created.

Check the committed references without a GPU:

```sh
pwsh -File scripts/Invoke-Tests.ps1 tests/test_gl_goldens.py -q
```

To author replacement reference bytes, explicitly generate into a **new directory** and review the diff before copying to the tracked folder:

```sh
python scripts/generate_gl_goldens.py --output ./new-gl-goldens
```

Normal tests, GPU qualification and CLI runs never regenerate or overwrite committed goldens. Updating any fixture, source algorithm, shader pin or expected PNG requires a reviewed, version-controlled change. The 64×48 source patterns intentionally fit the existing RGBA8 transport contract; the full render backend's texture/working-set checks remain authoritative.

## Actual GPU qualification and provenance

Install the released-compatible `gpu` extra, use the **matching checkout** and run:

```sh
python integration/qualify_gl_transition_goldens.py --backend egl --output gl-goldens-egl.json
```

A successful run compiles and executes each pinned transition on a real GL context, compares **all** readback RGBA bytes to the checked PNG, verifies the exact 2 uploads / 1 readback and per-pass texture-payload plan, confirms both original inputs remain immutable, and writes an exclusive-create JSON receipt (`framerudiments.gl-golden-qualification.v1`). The receipt retains source pins, manifest SHA-256, shader admission policy, explicit uniforms, observed and reference RGBA hashes, renderer/vendor/GL version, hardware-vs-software classification and measured payload-transfer counts. It does **not** claim OS-level physical adapter identity, verified hardware, driver-internal allocation measurements or perceptual acceptance. To pin a device string, pass `--expect-renderer` with a substring of its actual OpenGL renderer. Retain separate OS adapter and driver inventory for physical hardware acceptance.

On GitHub Actions, `tests/test_gl_goldens_egl.py` is **mandatory**, with no skip/fallback path. The GPU workflow separately runs the qualification tool and uploads the JSON as `gl-golden-provenance`, even when later GPU benchmarks fail. A missing EGL renderer, changed source pin or mismatched pixel is a hard failure. Verify the workflow and its committed SHA before treating the gate as satisfied.

The M9.4 restricted shader validator, explicit `trusted_shader: true` and all M9.3 working-set bounds remain active. Static validation is **not** a GPU security sandbox. No arbitrary third-party GLSL, untrusted shader service, ISF runtime or multipass image imports are enabled by these goldens.
